## 🔄 Complete Flow - Step by Step

### Phase 1: Terraform Infrastructure Creation

**Location:** `terraform/main.tf`

#### Step 1.1: Create Infrastructure
```bash
cd terraform
terraform apply -var-file=values/stage.tfvars
```

**What Terraform creates:**
1. VPC network, subnets, NAT, firewall rules
2. 5 VM instances (bastion, master, 2 workers, database)
3. SSH key pair (4096-bit RSA)
4. Saves SSH key to: `terraform/.ssh/provisioning_key`

#### Step 1.2: Generate hosts.yaml (AUTOMATICALLY)

**Location in code:** `terraform/main.tf` lines 128-150

```terraform

  filename = "${path.module}/../kubespray/inventory/k8s-cluster/hosts.yaml"
  
  content = templatefile("${path.module}/kubespray-inventory.tpl", {
    bastion_ip = "34.40.119.219"  # Extracted from created resources
    
    masters = [{
      name         = "k8s-master-1"
      ip           = "10.1.1.2"     # Private IP
      ansible_host = "10.1.1.2"
      public_ip    = "35.198.108.205"
    }]
    
    workers = [
      {
        name         = "k8s-worker-1"
        ip           = "10.1.2.3"
        ansible_host = "10.1.2.3"
        public_ip    = null

      {
        name         = "k8s-worker-2"
        ip           = "10.1.2.4"
        ansible_host = "10.1.2.4"
        public_ip    = null
      }
    ]
  })
}
```

**Generated file location:** `kubespray/inventory/k8s-cluster/hosts.yaml`

### Phase 4: Kubespray Git Submodule

**Location:** `ansible/kubespray/` (git submodule)

**Initialized with:**
```bash
git submodule update --init --recursive
```

**What this does:**
- Clones Kubespray repository from: `https://github.com/kubernetes-sigs/kubespray.git`
- Places it in: `ansible/kubespray/`
- This is a **submodule**, tracked by Git but separate repo

**Kubespray directory structure:**
```
ansible/kubespray/
├── cluster.yml                    # Main playbook (we used this!)
├── inventory/
│   └── k8s-cluster/
│       └── hosts.yaml             # Created by Terraform (symlinked)
├── roles/                         # Kubespray roles
├── requirements.txt               # Python dependencies
└── ... (other Kubespray files)
```

### Phase 5: Kubespray Kubernetes Deployment

**This is where the magic happens!**

#### Step 5.1: Setup Python Virtual Environment

```bash
cd /home/kaliuzhnyi/sytoss/projects/ultimate/Kubevanilla
python3 -m venv .venv
source .venv/bin/activate
pip install 'ansible>=2.17.3,<2.18.0'
```

**Why virtual environment:**
- System Ansible (2.16.3) too old
- Kubespray needs Ansible 2.17.3+
- Isolates dependencies

#### Step 5.2: Run Kubespray

**Command executed:**
```bash
cd ansible/kubespray

ansible-playbook \
  -i ../../kubespray/inventory/k8s-cluster/hosts.yaml \
  --become \
  --become-user=root \
  cluster.yml
```

**Breaking down the command:**

**`ansible-playbook`** - Ansible command to run playbooks

**`-i ../../kubespray/inventory/k8s-cluster/hosts.yaml`** - Path to inventory
- From `ansible/kubespray/` directory
- Go up two levels: `../../` 
- Then to: `kubespray/inventory/k8s-cluster/hosts.yaml`
- This is the file **GENERATED by Terraform**!

**`--become`** - Use sudo/become for privilege escalation

**`--become-user=root`** - Become root user (required for system changes)

**`cluster.yml`** - Main Kubespray playbook
- Located at: `ansible/kubespray/cluster.yml`
- This is the master playbook that includes all Kubespray roles

**What happens:**
1. Ansible reads `hosts.yaml` (generated by Terraform)
2. Connects to all nodes via SSH (using bastion ProxyCommand)
3. Executes Kubespray roles in order:
   - bootstrap-os
   - container-engine/containerd
   - kubernetes/preinstall
   - kubernetes/control-plane
   - kubernetes/node
   - network_plugin/calico
   - kubernetes-apps/cluster-addons
4. Kubernetes cluster is deployed!

**Duration:** ~15-30 minutes

## 🔍 Key File Locations Explained

### Terraform Templates

**`terraform/kubespray-inventory.tpl`**
- **Purpose:** Template for generating hosts.yaml
- **Used by:** Terraform `templatefile()` function
- **Variables:** `bastion_ip`, `masters`, `workers`
- **Output:** `kubespray/inventory/k8s-cluster/hosts.yaml`

**`terraform/inventory.tpl`**
- **Purpose:** Template for generating ansible/inventory.ini (not used in final setup)
- **Alternative:** We manually maintain `ansible/inventory.ini`

### Ansible Inventories

**1. `ansible/inventory.ini`** (for infrastructure management)
```ini
[bastion-host]
bastion ansible_host=34.40.119.219

[k8s-masters]
k8s-master-1 ansible_host=10.1.1.3 ansible_ssh_common_args='-o ProxyJump=bastion'

[k8s-workers]
k8s-worker-1 ansible_host=10.1.2.2 ansible_ssh_common_args='-o ProxyJump=bastion'
k8s-worker-2 ansible_host=10.1.2.3 ansible_ssh_common_args='-o ProxyJump=bastion'
```
**Used for:** Running `bastion.yml` playbook

**2. `kubespray/inventory/k8s-cluster/hosts.yaml`** (for Kubernetes deployment)
```yaml
all:
  hosts:
    k8s-master-1:
      ansible_host: 10.1.1.2
      # ... Kubespray-specific variables
```
**Used for:** Running Kubespray `cluster.yml`

**3. `ansible/k8s-inventory.ini`** (alternative, not used)
- Manual inventory file
- Not used in our deployment
- Can be deleted

### Q3: How exactly do we pass hosts.yaml to Kubespray?

```bash

```

**Path breakdown:**
- We are in: `ansible/kubespray/` directory
- Inventory at: `../../kubespray/inventory/k8s-cluster/hosts.yaml`
- `../../` goes up to project root
- Then into `kubespray/inventory/k8s-cluster/hosts.yaml`

**Alternative path (same file):**
```bash
# If you're in project root
ansible-playbook -i kubespray/inventory/k8s-cluster/hosts.yaml ansible/kubespray/cluster.yml
```

**Key point:** Kubespray **expects** inventory at `inventory/k8s-cluster/hosts.yaml` relative to its directory.

### Q4: Why do we have kubespray/ in two places?

**Answer:** It's actually ONE directory, accessed from different locations.

**Directory structure:**
```
Kubevanilla/
├── ansible/
│   └── kubespray/              ← Git submodule (actual location)
│       ├── cluster.yml
│       └── inventory/
│           └── k8s-cluster/
│               └── hosts.yaml  ← Generated by Terraform
│
└── kubespray/                  ← Symlink to ansible/kubespray
    └── inventory/
        └── k8s-cluster/
            └── hosts.yaml      ← Same file!
```

**Why symlink:**
- Terraform runs from `terraform/` directory
- Easier to access `../kubespray/` than `../ansible/kubespray/`
- Both paths point to same file

**Verify symlink:**
```bash
ls -la kubespray
# lrwxrwxrwx 1 user user 17 Dec 29 10:00 kubespray -> ansible/kubespray
```

### Q5: What's the difference between inventory.ini and hosts.yaml?

**Two separate inventories for different purposes:**

**1. `ansible/inventory.ini`** (Infrastructure management)
- **Format:** INI
- **Purpose:** Managing infrastructure (bastion, database)
- **Used by:** `ansible/playbooks/bastion.yml`
- **Manually maintained:** Updated when bastion IP changes
- **Example use:** Installing kubectl on bastion, creating users

**2. `kubespray/inventory/k8s-cluster/hosts.yaml`** (Kubernetes deployment)
- **Format:** YAML
- **Purpose:** Kubernetes cluster deployment
- **Used by:** Kubespray `cluster.yml`
- **Auto-generated:** Created by Terraform
- **Example use:** Installing Kubernetes on all nodes

**Summary:**
- Use `inventory.ini` for **infrastructure tasks**
- Use `hosts.yaml` for **Kubernetes deployment**

## 📝 Step-by-Step Deployment Commands

**Complete sequence from scratch:**

```bash
# 1. Clone repository
git clone https://github.com/DevOps-Team4/Kubevanilla.git
cd Kubevanilla
git checkout integration-yn

# 2. Initialize Kubespray submodule
git submodule update --init --recursive

# 3. Provision infrastructure with Terraform
cd terraform
terraform init -backend-config=backend/stage.properties
terraform apply -var-file=values/stage.tfvars
# Creates: VPC, instances, SSH key, hosts.yaml

# 4. Copy SSH key to home directory
cp .ssh/provisioning_key ~/.ssh/
chmod 600 ~/.ssh/provisioning_key

# 5. (Optional) Setup bastion
cd ../ansible
ansible-playbook -i inventory.ini playbooks/bastion.yml --vault-password-file .vault_pass

# 6. Setup Python virtual environment
cd ..
python3 -m venv .venv
source .venv/bin/activate
pip install 'ansible>=2.17.3,<2.18.0'

# 7. Deploy Kubernetes with Kubespray
cd ansible/kubespray
ansible-playbook \
  -i ../../kubespray/inventory/k8s-cluster/hosts.yaml \
  --become \
  --become-user=root \
  cluster.yml

# 8. Verify deployment
ssh bastion "kubectl get nodes"
```

8. ✅ Result: Fully functional Kubernetes cluster!
